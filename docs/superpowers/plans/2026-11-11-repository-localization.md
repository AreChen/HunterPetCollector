# 仓库规范与多语言实施计划

> 面向 Agent 型工作者：使用 superpowers:executing-plans 按任务实施；保持当前工作目录。

**目标：** 在当前插件目录建立规范的公开仓库，并支持英文和简体中文。

**架构：** 两个 TOC 在业务代码之前加载英文默认语言表和条件加载的中文翻译；保留内部标识与保存数据。上游来源经核实后记录，保留 GPLv3 和第三方致谢。

**技术栈：** WoW Lua、TOC、Git、GitHub。

**规格说明：** `docs/superpowers/specs/2026-11-11-repository-localization-design.md`

## 全局约束

不移动插件目录；不更改存档格式、通讯协议及命令；未知语言和缺失翻译回退英文；发布前核实上游授权。

## 审查重点

- 两种 TOC 的加载顺序和文件都有效。
- 非中文客户端、缺失翻译及格式参数保持可用。
- 不把程序标识、协议内容或持久化键当成展示文本翻译。
- 游戏 API 或数据无法返回中文名称时保留可读的英文。
- 原作者和第三方数据来源及许可不被覆盖或错误归属。

### Task 1：本地化

**文件：** 新建 `Locale/enUS.lua`、`Locale/zhCN.lua`；修改两个 TOC 和涉及用户可见文本的 Lua 文件。

- [ ] 建立英文默认表和按 `GetLocale()` 选择的中文覆盖表，缺失项回退英文。
- [ ] 将界面、选项、提示和聊天消息切换为本地化表；核对格式参数，保持内部数据不变。
- [ ] 检查 Lua 语法、TOC 加载顺序、默认语言和中文格式参数；游戏内检查两种语言和两个客户端，记录无法实际运行的部分。

### Task 2：仓库规范和来源

**文件：** 修改 `README.md`；按需新增 `.gitignore` 和贡献说明，保留 `LICENSE`。

- [ ] 核实原插件来源和授权，记录原作者、上游链接、本项目修改与第三方数据来源，不猜测缺失信息。
- [ ] 整理安装、开发、本地化与验证说明，排除不应入库的文件。
- [ ] 在当前目录初始化 Git，审查待提交文件，建立基线；来源核实后创建公开 GitHub 仓库并验证远端。
